# Story 1.3: Sincronização Cron Diária (Lancamentos2026 → Supabase)

**Status:** Ready
**Story ID:** 1.3
**Objective:** Implementar sincronização automática diária de transações via Vercel Cron Job

---

## 📋 Descrição

Criar Vercel Cron Job que executa diariamente lendo Lancamentos2026 via Google Sheets API. Valida dados (categoria conhecida, data válida, valor > 0), normaliza (lowercase, ISO format), insere/atualiza em `transactions` via upsert, registra em `sync_log` e implementa retry automático 3x em caso de erro.

**PRD Reference:** Seção "Google Sheets (Lancamentos2026) → Supabase" (p. 251-263)
**Architecture Reference:** Fluxo 3 "Sincronização Diária Automática"

---

## ✅ Acceptance Criteria

- [ ] Vercel Cron Job configurado em vercel.json
- [ ] Rota API `/api/sync/cron` implementada
- [ ] Leitura de 5 colunas: Data, Tipo (Entrada/Saída), Categoria, Valor, Descrição
- [ ] Validação: categoria conhecida, data válida (ISO), valor > 0
- [ ] Normalização: categoria lowercase, data ISO format
- [ ] Upsert em `transactions` (atualiza se existe por sheet_row_id, insere se novo)
- [ ] Teste: 10 transações inseridas/atualizadas corretamente
- [ ] Log em `sync_log`: rows_processed, rows_inserted, rows_updated, status
- [ ] Retry automático 3x antes de marcar erro
- [ ] Teste: Sync com erro → retry funciona e recupera
- [ ] Teste: Dados duplicados via Sheets → upsert evita duplicatas

## 📝 Dev Notes

- Vercel Cron syntax: `cron(0 8 * * *)` = 8h da manhã todo dia
- Sheet row_id deve ser rastreado para upsert (coluna implícita ou explícita)
- Retry com exponential backoff: 1s, 2s, 4s
- Timezone: Vercel usa UTC, considerar em logs
- Considerar rate limiting de Google Sheets API (quota diária)
- Log estruturado para análise (timestamp, status, counts, erros)
